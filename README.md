### Инструкция

# 📘 Инструкция для модератора системы «Мониторинг снега»

Документ описывает, как устроена система, где что находится, и что делать при типовых неполадках. Рассчитан на человека, который **не программист**, но умеет открывать ссылки, читать сообщения об ошибках и выполнять пошаговые действия.

---

## 1. Как устроена система (карта)

```
┌─────────────────┐      ┌──────────────────┐      ┌─────────────────┐
│  Работники      │ ───► │  GitHub Pages    │ ───► │  Google Apps    │
│  (браузер)      │      │  (форма)         │      │  Script (API)   │
└─────────────────┘      └──────────────────┘      └────────┬────────┘
                                                             │
                                                             ▼
                                                    ┌─────────────────┐
                                                    │  Google Sheet   │
                                                    │  «SnowMonitor»  │
                                                    └─────────────────┘
```

| Компонент     | Где находится                                                         | Что делает                                                       | Кто отвечает             |
| ------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------ |
| **Форма**     | GitHub Pages, ссылка вида `https://ваш-логин.github.io/репозиторий/`  | Показывает интерфейс, сохраняет ввод локально, отправляет данные | Владелец репозитория     |
| **Приёмник**  | Google Apps Script (`script.google.com`), URL оканчивается на `/exec` | Принимает POST, пишет строки в таблицу                           | Владелец Google-аккаунта |
| **Хранилище** | Google Sheet «SnowMonitor», лист `History`                            | Хранит историю всех отправок                                     | Владелец Google-аккаунта |

**Ключевой принцип:** данные сначала попадают в браузер работника (`localStorage`), и только при отправке (по расписанию или кнопкой) уходят в Google Sheet. Если работник закрыл вкладку — данные не потеряются, но и не отправятся автоматически, пока он не откроет страницу снова.

## 2. Быстрая диагностика: «что-то не работает»

Прежде чем что-то чинить — **определите, где именно проблема**. Задайте три вопроса:

### Вопрос 1: Открывается ли сама страница?

| Симптом                                    | Где искать                         |
| ------------------------------------------ | ---------------------------------- |
| Ссылка не открывается, 404                 | Проблема на GitHub Pages           |
| Страница открылась, но пустая / без стилей | Проблема в HTML-файле              |
| Страница открывается, всё видно            | Проблема не в GitHub — идём дальше |

### Вопрос 2: Что показывает индикатор в правом верхнем углу?

| Индикатор                     | Что значит                 | Где проблема             |
| ----------------------------- | -------------------------- | ------------------------ |
| ⚪ «Нет изменений»            | Ничего не вводили          | Всё нормально            |
| 🟢 «Сохранено ЧЧ:ММ»          | Данные записаны в браузере | Всё нормально            |
| 🔵 «Отправка…» (мигает долго) | Запрос ушёл, ответа нет    | Apps Script или интернет |
| 🔴 «Ошибка отправки»          | Запрос не прошёл           | Apps Script или URL      |
| Серый кружок без надписи      | JS-скрипт страницы сломан  | HTML-файл                |

### Вопрос 3: Появились ли данные в Google Таблице?

Откройте таблицу → лист `History` → проверьте **последнюю строку**:

- **Есть новая партия с временем отправки** → всё работает, проблема была в отображении.
- **Новой партии нет** → отправка не прошла, надо смотреть Apps Script.

## 3. Типовые неполадки и их решения

### 🔴 Проблема 1. Работник пишет: «Не отправляется, красный кружок»

**Что проверить:**

1. **Открыть консоль браузера.** Нажмите `F12` → вкладка **Console**. Попросите работника прислать скриншот или текст ошибок.
2. **Найдите одну из этих ошибок:**

#### Ошибка A: `Failed to fetch` / `NetworkError`

**Причина:** нет интернета **или** Apps Script недоступен.

**Решение:**

- Проверить интернет у работника.
- Открыть URL из `APPS_SCRIPT_URL` прямо в браузере — должен вернуть `[]` или JSON с данными.
- Если в браузере URL выдаёт страницу входа Google — **проблема в настройках доступа** (см. ниже «Проблема 3»).

#### Ошибка B: `JSON.parse: unexpected character` / `SyntaxError`

**Причина:** Apps Script вернул HTML (страницу ошибки) вместо JSON.

**Решение:**

- Открыть URL веб-приложения в браузере.
- Если там английский текст `Authorization required` — **проблема в доступе** (Проблема 3).
- Если там `Script function not found: doPost` — в скрипте пропала функция `doPost` (Проблема 4).

#### Ошибка C: `CORS policy` / `Access-Control-Allow-Origin`

**Причина:** редко, но бывает при неправильном `Content-Type`.

**Решение:**

- Проверить в `Weather.html` строку `'Content-Type': 'text/plain;charset=utf-8'` — она должна быть именно такой.
- Если кто-то поменял на `application/json` — вернуть `text/plain`.

---

### 🔴 Проблема 2. Данные не появляются в Google Таблице

**Проверить по порядку:**

1. **Лист `History` существует?**
   - Открыть таблицу → внизу должны быть вкладки листов.
   - Если листа нет — Apps Script создаст его при первой успешной отправке. Значит, отправок не было.
2. **Есть ли новые строки?**
   - Прокрутить вниз. Если последняя строка старше сегодняшнего дня — отправка не работает.
3. **Проверить Apps Script вручную** (см. раздел 4 «Тестирование Apps Script»).

---

### 🔴 Проблема 3. `Authorization required` / работник видит страницу входа Google

**Причина:** веб-приложение Apps Script развёрнуто с доступом «Все, у кого есть Google-аккаунт» или «Только я».

**Решение:**

1. Открыть [script.google.com](https://script.google.com) → выбрать проект **«SnowMonitor»** (или как назвали).
2. Справа вверху **«Развернуть» → «Управление развёртываниями»**.
3. У активного развёртывания нажать **✏️ (карандаш)**.
4. В поле **«У кого есть доступ»** выбрать **«Все»** (Anyone).
5. Нажать **«Развернуть»**.
6. **Проверить, что URL не изменился.** Если изменился — обновить его в `Weather.html` на GitHub и запушить.
7. При открытии URL в браузере должен отдаваться JSON (или `[]` для пустой таблицы), **без** страницы входа.

---

### 🔴 Проблема 4. Apps Script возвращает ошибку

**Как открыть логи:**

1. Открыть [script.google.com](https://script.google.com) → проект.
2. Слева иконка **«Выполнения»** (⏱ или 📋).
3. В списке найти последний запуск `doPost` (или `fetchSnowData`).
4. Кликнуть — увидеть текст ошибки.

**Типовые ошибки и решения:**

| Текст ошибки                                                            | Причина                                       | Решение                                                         |
| ----------------------------------------------------------------------- | --------------------------------------------- | --------------------------------------------------------------- |
| `Cannot read properties of null (reading 'getSheetByName')`             | Не задан `SPREADSHEET_ID`                     | Проблема 5                                                      |
| `Script function not found: doPost`                                     | Функция `doPost` удалена или переименована    | Восстановить из резервной копии                                 |
| `Exception: You do not have permission to call SpreadsheetApp.openById` | Скрипт не имеет доступа к таблице             | Проблема 5                                                      |
| `Exception: Service Spreadsheets failed while accessing document`       | Слишком частые запросы или таблица повреждена | Подождать 10–15 минут                                           |
| `Exception: Argument too large: value`                                  | Отправлено слишком много данных (>50 КБ)      | Проверить, не заполнена ли форма огромным текстом в комментарии |

---

### 🔴 Проблема 5. `SPREADSHEET_ID` не задан или неверный

**Как исправить:**

1. Открыть свою Google Таблицу «SnowMonitor».
2. Посмотреть на URL в браузере:
   ```
   https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz1234567890/edit
                                            └────── это и есть ID ──────┘
   ```
   Скопировать длинную строку между `/d/` и `/edit`.
3. Открыть Apps Script → найти строку:
   ```javascript
   const SPREADSHEET_ID = "ВАШ_ДЛИННЫЙ_ID";
   ```
4. Вставить скопированный ID.
5. Сохранить (`Ctrl+S`).
6. **Создать новую версию развёртывания** (см. раздел 5).

---

### 🔴 Проблема 6. Страница на GitHub Pages не открывается (404)

**Проверить:**

1. **Репозиторий существует и публичный?**
   - GitHub → ваш репозиторий → **Settings → General** → внизу «Danger Zone» → «Change repository visibility» → должно быть **Public**.
2. **GitHub Pages включён?**
   - **Settings → Pages** → должно быть «Your site is live at ...».
3. **Файл называется правильно?**
   - В корне репозитория должен быть `index.html` или `Weather.html`.
   - Если открываете корень (`/репозиторий/`) — нужен `index.html`.
   - Если открываете `/репозиторий/Weather.html` — нужен `Weather.html`.
4. **Прошло 1–2 минуты после пуша?**
   - GitHub Pages пересобирается с задержкой. Подождите и обновите страницу с `Ctrl+F5`.

---

### 🔴 Проблема 7. Работник заполнил, но данные в таблице неполные

**Возможные причины:**

1. **Работник заполнил не все районы** — это нормально, уйдут только заполненные.
2. **Работник закрыл вкладку до отправки** — данные остались в его `localStorage`. Он увидит их, когда снова откроет страницу, и сможет отправить кнопкой.
3. **Работники с разных устройств заполняли одно и то же** — **каждый отправит свою партию** со своим `batchId`. Это не ошибка, но в таблице будет несколько партий в одну минуту.

---

### 🔴 Проблема 8. Часы/прогресс-бар не работают

**Причина:** сломался JavaScript страницы (обычно после правок в HTML).

**Решение:**

1. Открыть страницу → `F12` → Console.
2. Если есть красные ошибки — попросить разработчика посмотреть. Частые причины:
   - Удалена переменная `SUBMIT_TIMES`.
   - Синтаксическая ошибка в HTML (лишняя или пропущенная кавычка).
3. **Откатить изменения** через GitHub:
   - Открыть репозиторий → вкладка **Commits** → найти предыдущий рабочий коммит → скопировать содержимое файла → вставить в текущий.

## 4. Тестирование Apps Script вручную

Если не уверены, работает ли приёмник — проверьте его **напрямую**, минуя форму.

### Тест 1: GET-запрос (простая проверка живости)

1. Скопировать URL веб-приложения (оканчивается на `/exec`).
2. Открыть в браузере.
3. **Ожидаемый результат:** JSON вида `[]` или `{"lastBatch":"...","rows":[...]}`.
4. **Плохой результат:** страница входа Google, HTML-ошибка, «Script function not found».

### Тест 2: POST-запрос (полная проверка записи)

Открыть терминал (или PowerShell на Windows) и выполнить:

**Linux / macOS:**

```bash
curl -X POST "ВАШ_URL_/exec" \
  -H "Content-Type: text/plain" \
  -d '{"submittedAt":"2026-11-17T12:00:00Z","districts":[{"district":"Тест","status":"Есть снег","comment":"проверка"}]}'
```

**Windows PowerShell:**

```powershell
$body = '{"submittedAt":"2026-11-17T12:00:00Z","districts":[{"district":"Тест","status":"Есть снег","comment":"проверка"}]}'
Invoke-RestMethod -Uri "ВАШ_URL_/exec" -Method Post -ContentType "text/plain" -Body $body
```

**Ожидаемый ответ:** `{"success":true,"batchId":"...","count":1,"submittedAt":"..."}`

**После теста:** в Google Таблице → лист `History` должна появиться строка «Тест». Её можно удалить — это тестовые данные.

## 5. Как обновить код Apps Script безопасно

Любое изменение в скрипте требует **новой версии развёртывания**, иначе работники получат старую.

### Порядок действий:

1. **Сделать резервную копию.** Открыть Apps Script → выделить весь код → `Ctrl+C` → вставить в блокнот → сохранить файл `backup_YYYY-MM-DD.gs`.
2. Внести изменения.
3. **Сохранить** (`Ctrl+S`).
4. **Развернуть → Управление развёртываниями → ✏️ → Версия: «Новая версия» → Развернуть**.
5. **Проверить URL.** Если он изменился — обновить в `Weather.html`, закоммитить на GitHub.
6. **Проверить работу** через Тест 2 из раздела 4.
7. Если что-то сломалось — откатить: вставить старый код → снова «Новая версия» → Развернуть.

> ⚠️ **Не удаляйте старое развёртывание сразу после обновления** — если новая версия сломается, можно быстро вернуть старую через **«Архивировать» / «Восстановить»**.

## 6. Как обновить форму на GitHub Pages

1. Открыть репозиторий на github.com.
2. Найти `index.html` (или `Weather.html`) → нажать на файл → значок **✏️ (карандаш)**.
3. Внести изменения.
4. Прокрутить вниз → **«Commit changes»** → сообщение (например, «fix: обновил URL скрипта») → **«Commit»**.
5. Подождать 1–2 минуты, проверить страницу с `Ctrl+F5`.

**Что НЕЛЬЗЯ менять без разработчика:**

- Структуру переменных (`DISTRICTS`, `SUBMIT_TIMES`, `APPS_SCRIPT_URL`) — их **можно**, но только значения внутри `'...'`.
- Теги `<script>` и `<style>` — трогать только внутри, не удалять сами теги.
- Логику функций `submitData`, `tickClock`, `checkSchedule` — не трогать.

## 7. Регулярное обслуживание (чек-лист)

Раз в неделю:

- [ ] Открыть Google Таблицу → убедиться, что идут новые строки.
- [ ] Прокрутить лист `History` → проверить, нет ли пустых `Партия` или `Район`.
- [ ] Открыть GitHub → вкладка **Insights → Traffic** → посмотреть, заходят ли работники.
- [ ] Открыть Apps Script → **Выполнения** → проверить, нет ли повторяющихся ошибок.

Раз в месяц:

- [ ] Скачать резервную копию Google Таблицы (**Файл → Скачать → XLSX**).
- [ ] Скачать резервную копию Apps Script (скопировать код в файл).
- [ ] Скачать резервную копию HTML с GitHub (**Code → Download ZIP**).
- [ ] Сохранить все три файла в папку `backup_ГГГГ-ММ/`.

## 8. Что делать, если сами не справляетесь

**Собрать для разработчика:**

1. Скриншот страницы с ошибкой (с открытой консолью `F12 → Console`).
2. URL из `APPS_SCRIPT_URL` (из HTML-файла).
3. Скриншот листа **«Выполнения»** в Apps Script (последние 10 запусков).
4. Время (МСК) и часовой пояс, когда произошла ошибка.
5. Что делал работник перед ошибкой (заполнял / нажимал кнопку / ждал автоматической отправки).

С этими данными разработчик решит проблему за 10–15 минут.

## 🎯 Главное правило

**Если что-то сломалось — сначала посмотрите, где именно:**

1. Форма (GitHub) — не открывается, поля не работают, кнопки не нажимаются.
2. Отправка (Apps Script) — красный кружок, ошибка в консоли, нет данных в таблице.
3. Хранение (Google Sheet) — данные пришли, но в неправильные столбцы или не туда.

**Не чините всё сразу** — найдите звено, где произошёл сбой, и работайте с ним. В 90% случаев это одно из трёх: (1) URL Apps Script изменился, (2) доступ к веб-приложению не «Все», (3) в HTML-файле случайно удалили кавычку или тег.
